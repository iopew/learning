## 2026-10-21 — Итерация 0: идея

**Запрос.** Сначала: «сервис, который вверху показывает показатели компа и температуру». Потом идея поменялась: «реальный трекер активности на маке, до каждой минуты, со статистикой за день, неделю, месяц, 60, 90, 180 дней и год».

**Обсуждение и выбор:**
- Что записывать: «всё плюс сайты», то есть приложение, заголовок окна и адрес вкладки.
- Кто пишет код: «код пишешь и проверяешь ты, я проверяю результат».
- Где смотреть статистику: «нужно именно приложение на маке, в меню-баре».
- Язык: Swift + SwiftUI. Нативное приложение в строке меню с графиками и системными разрешениями проще всего сделать на нём (см. [[03 - Решения]], №2).

**Ограничение среды.** Разработка идёт в облачном Linux-контейнере, где Swift для macOS не собирается. Поэтому каждую сборку и все тесты гоняем на настоящем Mac в GitHub Actions (`macos-15`). Репозиторий публичный, так что минуты macOS бесплатные.

## 2026-10-21 — Итерация 2: окно приложения, автообновление, тема, документация

**Запросы пользователя** (пришли один за другим):
1. «Это должно быть ещё и приложением, не просто окошком». Убрать «Claude» из шапки.
2. «Чтобы при смене кода приложение обновлялось само» или «появлялась кнопка Update».
3. Батарея (расход, на что тратится, сколько раз заряжалась), состояние Mac, рекомендации («меньше ютуба сегодня»). Вопрос: не будет ли само приложение много тратить?
4. Светлая и тёмная тема, английский язык. «Подумай и дай идеи».
5. README и отдельная документация с отчётом о каждом шаге.

**План.** Сначала окно, автообновление и тема. Автообновление нужно раньше всего: тогда всё остальное (язык, батарея, рекомендации) приедет к пользователю само. Батарея, язык и рекомендации идут в итерацию 3.

**Что сделано:**
1. **Шапка:** убрано «текущее приложение», остался статус («Записываю», «Пауза»…). Отчёт за сегодня теперь обновляется вместе со счётчиком каждые 5 секунд (`StatsModel.refreshIfLive`), длинные периоды раз в минуту. Обновление идёт только пока окно видно.
2. **Большое окно** (`MainWindow.swift`):
   - `NSWindow` 1120×760 с SwiftUI внутри: слева периоды и графики, справа списки;
   - значок в Dock, пока окно открыто (или всегда, по настройке);
   - открывается двойным кликом в Finder или Launchpad и кнопкой «Окно» в окошке меню;
   - ⌘Q закрывает окно, «Выйти» завершает приложение;
   - при запуске вручную окно открывается, при автозапуске и после обновления нет.
3. **Иконка:** `tools/make_icon.py` рисует `Resources/AppIcon.png`, `build.sh` превращает её в `AppIcon.icns` (`sips` + `iconutil`).
4. **Тема:** настройка «Как в системе / Светлая / Тёмная» через `NSApp.appearance`.
5. **Автообновление** (`Updater.swift`, `UpdateFeed.swift`, `Resources/local-sign.sh`); подробно в [[01 - Архитектура]] → «Обновление и подпись»:
   - CI публикует релиз `activity-tracker-build-N` после всех проверок;
   - приложение проверяет релизы раз в 30 минут и ставит новую сборку само или по кнопке «Обновить»;
   - постоянная локальная подпись, чтобы разрешения не слетали;
   - установщик с откатом и защитой от зацикливания;
   - сборка, установленная вручную, один раз сама переходит на постоянную подпись.
6. **CI** проверяет всё это на настоящем Mac:
   - подпись двух разных сборок даёт одинаковое требование;
   - сквозной тест: ad-hoc «сборка 1» ставится в /Applications, сама переподписывается, потом обновляется до новой сборки через `--update-from-zip` и продолжает работать с той же подписью;
   - замер ресурсов (процессор, память, энергия) за минуту;
   - публикация релиза.
7. **Документация:** `docs/00–04` и правило вести журнал в `ActivityTracker/CLAUDE.md`.

**Как проверялось до отправки на Mac.** Сборки Swift здесь нет, поэтому код перед push прошёл независимое ревью: четыре агента смотрели с разных сторон (компилируемость, обновление и подпись, поведение AppKit, CI-скрипт), а каждую находку отдельно проверял агент-скептик. **Проверка на Mac:** [запуск 39608074816](https://github.com/iopew/learning/actions/runs/39608074816), коммит `68ef926`. **Зелёный с первого раза:**
- компиляция и тесты прошли;

**Независимое ревью** (4 направления, у каждого скептик-проверяющий). Найдено и исправлено:
1. **Опасно:** если не удалось убрать старую версию в резерв, ветка «восстановления» удаляла рабочее приложение. Теперь восстановление идёт только если резервная копия действительно сделана, а иначе просто перезапускается старая версия.
2. Неудачная сборка запоминалась только при «не поднялась». При других сбоях автообновление повторяло бы попытку каждые 30 минут с перезапуском. Теперь любая неудача помечает сборку.
3. Нет взаимоисключения установщиков. Добавлен `flock` на `Updates/install.lock`.
4. Статус `open` игнорировался, у передачи управления не было «сторожа». Теперь ошибка `open` видна. Если установщик за 90 секунд не забрал управление, обновление показывает ошибку. Если переход на постоянную подпись не состоялся за 60 секунд, приложение запускается как обычно.
5. Установщик опрашивал список запущенных приложений, не прокручивая run loop (на CI это сработало, но надёжности нет). Теперь между опросами крутится `RunLoop`, а живость процесса проверяется через `kill(pid, 0)`.
6. ⌘Q проверялся по физической клавише Q, что ломалось на других раскладках. Теперь проверяется любое ⌘-нажатие, которое вызвало выход.
7. `local-sign.sh`: при сбое создания связки она могла остаться в списке связок. Добавлен `trap`, ошибка `unlock-keychain` теперь обрабатывается.
8. Скачанные архивы не удалялись. Теперь чистятся после распаковки и при запуске (кроме `previous.app`).
9. CI: повторный запуск того же прогона падал на уже существующем теге. Теперь в этом случае ассет перезаливается. Изменения только в `docs/`, `WIP/` и `*.md` больше не запускают сборку и релиз.

## 2026-10-21 — Итерация 2.1: удаление данных, приватные окна v2, исправления по ревью

**Запрос.** «Не вижу функции удаления, до сих пор трекаются сайты из инкогнито». Удаление я пообещал, но не сделал. Определение инкогнито работало только через AppleScript, а у некоторых браузеров (и у Safari) такого признака нет.

**Сборка 5 упала на публикации** ([запуск 39609426693](https://github.com/iopew/learning/actions/runs/39609426693)):
- *Причина:* моя же правка «удалять скачанный архив после распаковки». В CI сквозной тест ставит обновление из `.build/ActivityTracker.zip`, установщик удалил этот файл, и публиковать стало нечего.
- *Исправление:* удаляются только архивы из своей папки `Updates/`. CI отдаёт тесту копию и проверяет, что оригинал на месте.
- Все остальные проверки сборки 5, включая сквозное обновление, прошли.

**Удаление данных** (`ActivityStore.erase`):
- что можно удалить: сайт целиком, приложение целиком, всё после момента (последние 15 минут, час, сегодня), всю историю;
- удаление насовсем: `PRAGMA secure_delete=ON` затирает освобождённые страницы, `wal_checkpoint(TRUNCATE)` убирает копии из WAL;
- открытое событие сбрасывается, чтобы следующий сэмпл не продлевал удалённую строку;
- в интерфейсе: корзина при наведении на строку в списках «Приложения» и «Сайты», правый клик, меню «Забыть» в окне и окошке строки меню, раздел «Данные» в настройках; всегда с подтверждением;
- 4 новых теста.

**Приватные окна v2** (`PrivateWindowDetector`). Вдобавок к AppleScript приложение один раз в фоне осматривает панель каждого нового окна браузера. Ищет значок «Incognito / Инкогнито / InPrivate / Private / Частный доступ…», пропуская содержимое страницы (`AXWebArea`) и вкладки (`AXTabGroup`). Метка должна быть короткой и совпадать целиком или первым или последним словом. Пока окно не проверено, его тик не записывается. Параллельно идёт исследование (агенты в интернете), какие признаки на самом деле у Safari, Яндекса и Chrome.

**Ревью, второй круг** (направления «AppKit» и «CI»). Подтверждено и исправлено:
1. **После полуночи статистика залипала на вчерашнем дне.** Окно писало «Вчера» и переставало обновляться. Теперь, пока пользователь смотрит «сегодня», день сам переходит на новый.
2. **После ручной установки главное окно не открывалось.** Переход на постоянную подпись перезапускал приложение в фоне. Теперь ручной запуск заканчивается открытым окном (`--show-window` передаётся через установщик).
3. Автообновление закрывало открытое окно. Теперь, пока окно открыто, обновление не ставится само, а ждёт кнопки. После обновления по кнопке окно открывается снова.
4. Выход мышкой из меню приложения останавливал запись. Теперь, пока окно открыто, любой ручной выход только закрывает окно. Завершают приложение кнопки «Выйти», выход из системы и установщик (их Apple Event `quit` пропускается).
5. После переключения `.accessory → .regular` строка меню могла показывать меню чужого приложения. Добавлена повторная активация на следующем проходе run loop.
6. CI: проверка «приложение запущено» засчитывала и установщик (`pgrep -x`), теперь она смотрит только путь в /Applications. Добавлен `concurrency`, чтобы публикации не шли параллельно.
- Скептик опроверг три находки направления «компилируемость» (устаревший список приложений, статус `open`, ⌘Q по коду клавиши). Они всё равно закрыты предыдущими правками.
- Итог ревью: 5 подтверждено, 18 опровергнуто. Почти все опровергнутые находки к моменту проверки уже были исправлены в коде, поэтому скептик их не воспроизвёл. Последняя подтверждённая находка (удержание ⌘Q: повтор нажатия после закрытия окна выходил из приложения по-настоящему, то же для свёрнутого окна) исправлена в итерации 3.

**Ответ пользователя:** инкогнито было в **Safari**. «Если определять сложно, одной кнопки удалить хватит». Удаление уже в сборке 6. Для Safari попросили снимок окна через «Диагностику»; исследование признаков идёт в фоне.

## 2026-10-21 — Итерация 3: язык, батарея, состояние Mac, рекомендации

**Запросы** (накопились раньше):
- батарея: на что тратится, расход, сколько раз заряжалась, «вся статистика»;
- рекомендации вроде «меньше YouTube сегодня»;
- «полное состояние Mac»;
- английский язык;
- вопрос «не будет ли приложение много тратить?» Ответ: замер в CI показал CPU 0,1%, энергию 0,1, память ~52 МБ.

**Что сделано:**
1. **Язык.** `L.tr("рус", "eng")` во всём интерфейсе (124 строки заменены скриптом, остальные вручную). Переключатель «Как в системе / Русский / English», смена без перезапуска (`.id(settings.language)` + пересборка отчётов). Единицы и даты тоже по языку.
2. **Батарея и система:**
   - `SystemSampler` раз в минуту в фоне (IOKit, Mach, sysctl, `proc_pid_rusage`);
   - `SystemStore`: таблицы `system_samples`, `app_energy`, `charge_events`, отчёт с расходом %/ч через оконную функцию `LAG`, без разрывов сна;

## 2026-10-21 — Итерация 3.2: зависание при скрытом значке

**Жалоба:** «приложение до сих пор зависает» (сборка 8): окно не открывается, вращается радужный круг.

**Как нашли.** Пользователь прислал `ps` (процесс на 100% CPU) и вывод `sample <pid>`. В выводе главный поток бесконечно ходит по кругу:
`MenuBarExtraController.updateConfiguration` → `_setVisible` → KVO → `MenuBarExtraController.observeValue` → `Binding.wrappedValue.setter`
→ замыкание в `ActivityTrackerApp.menuBarShown` → `Settings.menuBarStyle.didset` → перестройка сцены (`appGraphDidChange` → `makeMainMenu`) → снова `updateConfiguration`.
Память выросла до 3,1 ГБ.

**Причина.** В `MenuBarExtra(isInserted:)` передавалась привязка, которая при сообщении «значок скрыт» записывала `menuBarStyle = .hidden`.
`@Published` оповещает подписчиков даже тогда, когда присваивается то же значение. В итоге при выбранном «Скрыть» каждое такое оповещение
заново перестраивало сцену, а SwiftUI снова сообщал «скрыт». Петля начинается сразу при запуске, если значок скрыт. Фикс сборки 8
(osascript в фоне) был нужен, но эту петлю не задевал.

**Исправление:**
- Привязка `isInserted` только читает настройку, её запись ничего не делает.
- Сцена `App` наблюдает только `Settings`. Значок строки меню вынесен в отдельный вид `MenuBarLabel`, и тик трекера раз в 5 секунд
  перерисовывает только его, а не всю сцену с главным меню. Раньше `App` наблюдал tracker, stats и updater.
- `didSet` у `appearance`, `alwaysShowInDock` и `language` ничего не делают, если значение не изменилось.

Удаление сайта или приложения удаляет и тексты, на которые больше никто не ссылается, иначе заголовки удалённого сайта остались бы в файле.

   - отчёты считают средние с весом по времени (`SUM(x*interval)/SUM(interval)`), поэтому свёрнутые часы и свежие минуты смешиваются правильно.

## 2026-10-26 — Итерация 10: ревью и проверка безопасности перед публикацией, сборка 23

**Запрос:** «давай тогда сделай ревью, и тесты на безопасность… если получится хороший продукт, я могу его опубликовать»; «sql injection, code injection, csrf tokens, pepper and all of that»; «https only». Три независимых ревью (безопасность, правильность, производительность), агенты на Sonnet с effort medium по просьбе владельца.

**Безопасность:**
- **SQL-инъекции:** все значения передаются через привязку параметров (`?`). Имена таблиц и колонок в SQL — только константы из кода. `sql` в Терминале открывает базу только на чтение, второй оператор после `;` не выполняется. Тест: заголовки вида `'); DROP TABLE events; --` хранятся как текст.
- **Обновления (подмена кода):**
  - curl только по https, в том числе после редиректов (`--proto =https --proto-redir =https`), не больше 200 МБ;
  - ссылка принимается только вида `https://github.com/iopew/learning/releases/download/<тег>/ActivityTracker.zip`;
  - номер сборки не может прыгнуть больше чем на 10 000 (иначе поддельная «сборка 2 000 000 000» заблокировала бы все настоящие);
  - перед распаковкой проверяется список файлов архива (один `ActivityTracker.app`, без `..` и абсолютных путей), после — нет ли ссылок наружу; подпись проверяется `codesign --verify --deep --strict`;
  - установщик заменяет только `ActivityTracker.app`;
  - у всех внешних процессов есть тайм-аут.
- **CSRF-аналог — ссылки `activitytracker://`:** любая веб-страница может открыть такую ссылку, поэтому ссылка теперь только открывает окно. Пауза и продолжение — только из Терминала; длительность проверяется (не NaN, не бесконечность, не больше суток).
- **Pepper и соль:** паролей в приложении нет, хранить нечего — не применимо.
- **CSV:** значение, которое начинается с `= + - @`, табуляции или CR, получает апостроф, чтобы Excel/Numbers не выполнили формулу из заголовка страницы.
- **Открытие чужой базы:** проверяется размер (до 4 ГБ), `quick_check` и отсутствие триггеров; у всех соединений `trusted_schema=OFF`.
- **Файлы:** `umask 077`, папка данных 700, базы 600; удаление с `secure_delete` и checkpoint, удаляются и осиротевшие заголовки/адреса, сети без замеров, автозагрузка и размеры папок.
- **Пинг:** адрес роутера проверяется как IPv4 (`inet_pton`) перед запуском `/sbin/ping`.
- **Местоположение:** запрос больше не всплывает сам — только по кнопке в «Сети». Добавлено описание `NSLocalNetworkUsageDescription`.
- **CI:** права по умолчанию `contents: read`, публикация — отдельная задача с `contents: write` на Ubuntu, actions закреплены по SHA.

**Правильность:**
- граница дня считается по часам на стене (переход на летнее/зимнее время больше не сдвигает её);
- отчёты `kernel_task …cpu_resource.diag` больше не считаются паникой ядра; «zed» — программа, а не служба;
- средние на графиках взвешены по времени, сводка по часам не делит на NULL;
- зарядка, отключённая после конца окна, не теряется; замена батареи не ломает прогноз износа;
- пересчёт дней одним UPDATE в SQLite вместо загрузки всех строк.

**Производительность:** сводка по часам — по одному дню в транзакции; удаление, архив, `log show` — в фоне; вызовы Accessibility с тайм-аутом 0,2 с; опубликованные значения меняются только при изменении; загрузки статистики не копятся; сканирование папок не идёт от батареи и в режиме энергосбережения.

**Тесты:** `SecurityTests.swift` — SQL-инъекции, чтение-only `sql`, триггеры в архиве, не-база и слишком большой файл, удаление заголовков, формулы в CSV, доверенные ссылки обновления, отравленная лента, список архива, пауза, паника/служба, переход на зимнее время, пересчёт дней через SQL.

**CI:** [сборка 23](https://github.com/iopew/learning/actions/runs/40309259138) зелёная с первого раза (коммит `3dafbe1`): тесты, сборка, сквозное обновление уже с новыми проверками архива и подписи; публикация впервые отдельной задачей с правом записи.

**Осталось перед публикацией (нужно решение владельца):**

- подпись релизов ключом Ed25519 (нужен секрет в GitHub, его может добавить только владелец);
- публиковать релизы только с `main` и защитить ветку (сейчас публикует любая зелёная `claude/*`);
- локальная подпись хранит пароль временной связки ключей в скрипте — после Developer ID она не нужна;
- политика конфиденциальности (данные не покидают Mac).
