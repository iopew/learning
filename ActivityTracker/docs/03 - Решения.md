# Журнал решений

Почему сделано именно так. Новые решения добавляются в конец таблицы. Отменённые решения зачёркиваются, но не удаляются.

| # | Решение | Почему |
|---|---|---|
| 1 | ~~Индикатор CPU и температуры в строке меню на Go~~ → трекер активности | Пользователь поменял идею: нужен учёт того, на что уходит время, с точностью до минуты |
| 2 | Swift + SwiftUI, а не Go | Нативное приложение в строке меню с графиками и системными разрешениями. На Go пришлось бы тянуть cgo, systray и отдельную веб-страницу для графиков |
| 3 | Пишу код и проверяю я, пользователь проверяет результат | Так попросил пользователь |
| 4 | Записываются приложения, заголовки окон и сайты | Выбор пользователя («всё это плюс сайты») |
| 5 | Хранение отрезками (start/end), сэмпл раз в 5 секунд | Точность до секунд, база маленькая (тысячи строк в день). Минутная сетка и сессии вычисляются из отрезков |
| 6 | SQLite через системный `SQLite3`, без сторонних библиотек | Ноль зависимостей, WAL позволяет писать и читать одновременно |
| 7 | Модуль `ActivityCore` без AppKit | Логику можно тестировать (`swift test`), не трогая macOS-интерфейс |
| 8 | Проверка на настоящем Mac через GitHub Actions (`macos-15`) | Разработка идёт в облачном Linux, где Swift для macOS не собрать. Репозиторий публичный, минуты macOS бесплатны |
| 9 | Простой: порог 3 минуты. Видео и звонки (когда экран не гаснет) считаются активностью | Чтобы просмотр видео не выпадал из статистики. Отключается в настройках |
| 10 | Неделя начинается с понедельника, дни считаются по местному времени | Привычно для пользователя |
| 11 | Периоды скользящие (последние N дней до выбранного дня) | Пользователь назвал периоды 60, 90 и 180 дней, а они бывают только скользящими. Неделя и месяц сделаны так же для единообразия |
| 12 | Из шапки убрано «текущее приложение» | Пользователь принял «Claude Claude» (это было активное приложение) за мусор |
| 13 | Большое окно на AppKit (`NSWindow` + `NSHostingController`), а не SwiftUI `Window` | Его нужно открывать отовсюду: из окошка в меню, из Dock, повторным запуском. Значок в Dock виден только пока окно открыто |
| 14 | ⌘Q в окне закрывает окно, а не приложение | Трекер должен работать всегда. Привычное ⌘Q не должно случайно останавливать запись |
| 15 | Автообновление из GitHub Releases | Пользователь хочет, чтобы изменения приходили сами, без переустановки |
| 16 | Своя постоянная подпись (самоподписанный сертификат в отдельной связке) | Иначе после каждого обновления терялись бы разрешения «Универсальный доступ» и «Автоматизация». Сертификат создаётся на Mac пользователя и не покидает его |
| 17 | CI собирает ad-hoc, переподпись делается на Mac пользователя | Не нужно хранить ключ подписи в секретах GitHub |
| 18 | Установщик — это сама новая копия приложения (`--install-update`), а не shell-скрипт | Запуск через `open -n` даёт отдельный процесс в launchd, который переживает выход старой версии. Плюс замена с откатом |
| 19 | Номер сборки = номер запуска CI | Монотонно растёт и совпадает с `CFBundleVersion` и тегом релиза |
| 20 | Релизы публикуются с `main` и `claude/*`, хранятся 5 последних | Изменения доходят до пользователя сразу после зелёной проверки |
| 21 | Единственный сетевой запрос — проверка обновлений. Отключается в настройках | Пользователю важно, что всё локально |
| 22 | Тема оформления: как в системе, светлая, тёмная (`NSApp.appearance`) | Просьба пользователя |
| 23 | Документация в `docs/` и журнал каждого шага, правило в `ActivityTracker/CLAUDE.md` | Просьба пользователя: «чтобы в будущем не гадать, как что-то сделано» |
