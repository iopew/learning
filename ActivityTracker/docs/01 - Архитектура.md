# Архитектура

## Общая схема

```
┌──────────── ActivityTracker.app ────────────────────────────────────────────┐
│                                                                              │
│  Tracker (каждые 5 с, главный поток)                                         │
│    ├─ NSWorkspace.frontmostApplication      → какое приложение               │
│    ├─ Accessibility (AXUIElement)           → заголовок окна                 │
│    ├─ AppleScript в браузер                 → адрес вкладки                  │
│    └─ CGEventSource / IOPM assertions       → простой, видео/звонок          │
│           │                                                                  │
│           ▼  record(sample)                                                  │
│  ActivityStore ──► SQLite (WAL) ~/Library/Application Support/…/activity.sqlite
│           ▲  report(range, anchor)  (фоновая очередь, отдельное соединение)  │
│           │                                                                  │
│  StatsModel ×2 (окошко в меню, большое окно) ──► SwiftUI-вьюхи               │
│                                                                              │
│  Updater (раз в 30 мин) ── GitHub Releases ──► Installer (замена + откат)    │
└──────────────────────────────────────────────────────────────────────────────┘
```

Код разделён на два модуля SwiftPM:

| Модуль | Что внутри | Зависит от macOS-интерфейса? |
|---|---|---|
| `ActivityCore` | база, склейка событий, отчёты, календарь, форматирование, разбор ленты обновлений | нет. Покрыт тестами (`swift test`) |
| `ActivityTracker` | сборщики, таймер, окна, SwiftUI, обновление, установщик | да |

## Как записывается время

Каждые 5 секунд `Tracker.tick()` спрашивает систему, что сейчас на экране, и делает одну из двух вещей:
- если пользователя нет (пауза, сон, заблокирован экран или простой дольше порога), вызывает `store.endStreak(at:)`, и время перестаёт капать;
- иначе передаёт `Sample` (приложение, заголовок, URL) в `store.record(_:at:interval:)`.

**Склейка, как у heartbeats в ActivityWatch.** В базе хранятся не точки, а **отрезки** (`events`). Каждый сэмпл засчитывается на 5 секунд вперёд. Дальше `record` смотрит на текущий открытый отрезок:
- **то же приложение, заголовок и URL, тот же день, без разрыва:** у отрезка просто сдвигается `end_at`;
- **что-то другое:** открывается новый отрезок, а кредит старого обрезается до момента переключения.

Переключение приложения ловится сразу по уведомлению `didActivateApplication`, а не через 5 секунд.

**Полночь.** Каждый отрезок принадлежит одному дню (поле `day`, местное время). После полуночи начинается новый отрезок.

## База данных

Один файл SQLite в режиме WAL. Через два соединения: одно пишет в главном потоке, второе читает отчёты в фоне.

```sql
CREATE TABLE events(
    id INTEGER PRIMARY KEY,
    day TEXT NOT NULL,        -- '2026-10-21', местный день начала отрезка
    start_at REAL NOT NULL,   -- unix-время, секунды
    end_at REAL NOT NULL,
    bundle_id TEXT NOT NULL,  -- 'com.apple.Safari'
    app TEXT NOT NULL,        -- 'Safari'
    title TEXT NOT NULL DEFAULT '',
    url TEXT NOT NULL DEFAULT '',
    domain TEXT NOT NULL DEFAULT ''   -- 'youtube.com' (без www)
);
CREATE INDEX events_day ON events(day);
```

## Отчёты

`ActivityStore.report(range:anchor:)` считает всё одним вызовом:
- итоги по дням (`GROUP BY day`): общее время, число активных дней, среднее за активный день;
- приложения (`GROUP BY bundle_id`) и топ-5 заголовков для первых 15 приложений;
- сайты (`GROUP BY domain`);
- столбики графика: по дням, а если период длиннее 92 дней, то по неделям с понедельника;
- **только для дня:**
  - минутная сетка из 1440 клеток (в каждой то приложение, которое заняло большую часть минуты);
  - почасовой график (топ-5 приложений, остальное в «Другое»);
  - хронология (подряд идущие отрезки одного приложения с разрывами до минуты склеиваются в сессию).

## Окна

- **Строка меню** (`MenuBarExtra`, стиль `.window`): время за сегодня и окошко `PopoverView`.
- **Большое окно** (`MainWindowController`): обычное `NSWindow` с SwiftUI внутри.
  - Пока окно открыто, приложение переключается в режим `.regular`, и появляется значок в Dock и в ⌘-Tab. После закрытия возвращается `.accessory`, если в настройках не включено «всегда в Dock».
  - Двойной клик по приложению в Finder или Launchpad (`applicationShouldHandleReopen`) открывает окно.
  - ⌘Q в окне только закрывает окно, запись продолжается. Кнопка «Выйти» завершает приложение по-настоящему.
- Оба вида строятся из общих блоков: `StatsControls`, `ReportOverview`, `ReportLists`. Пока вид на экране, он обновляется каждые 5 секунд для «сегодня» и раз в минуту для длинных периодов.

## Обновление и подпись

### Зачем своя подпись

macOS запоминает разрешения («Универсальный доступ», «Автоматизация») по **подписи** приложения. У ad-hoc подписи хэш меняется с каждой сборкой, поэтому после каждого обновления разрешения терялись бы.

`Resources/local-sign.sh` при первом запуске создаёт **самоподписанный сертификат** только на этом Mac:
- ключ лежит в отдельной связке `~/Library/Application Support/ActivityTracker/Signing/signing.keychain-db`;
- эта связка не добавляется в список связок пользователя, поэтому другие приложения её не видят и не просят пароль.

Каждая сборка подписывается этим ключом. Требование подписи (`codesign -d -r-`) у всех сборок получается одинаковое: `identifier "com.iopew.ActivityTracker" and certificate leaf = H"…"`. Поэтому разрешения сохраняются.

### Цепочка обновления

1. **CI** (GitHub Actions, macOS) при каждом push в `main` или `claude/*`, который меняет `ActivityTracker/`:
   - прогоняет тесты, собирает приложение, проверяет его;
   - проводит сквозной тест обновления;
   - публикует релиз `activity-tracker-build-N`, где N — номер запуска CI и он же `CFBundleVersion`;
   - хранит 5 последних релизов.
2. **Updater** раз в 30 минут (и по кнопке) запрашивает `GET api.github.com/repos/iopew/learning/releases`. `UpdateFeed` выбирает самую новую сборку с `ActivityTracker.zip`.
3. Если сборка новее и включена автоустановка, начинается установка. Иначе в окне появляется полоса с кнопкой «Обновить».
4. **Установка:**
   - скачать zip;
   - `Installer.stage`: распаковать в `~/Library/Caches/…/Updates/staged`, проверить bundle id и номер сборки, переподписать локальным ключом;
   - запустить **новую копию** командой `open -n -g … --args --install-update /Applications/ActivityTracker.app`.
5. **Режим установщика** (в новой копии, до появления интерфейса):
   - попросить старую версию завершиться (если не выходит за 15 секунд, завершить принудительно);
   - убрать старую версию в `Updates/previous.app`, скопировать себя на её место (`ditto`);
   - запустить установленную версию с `--background`;
   - убедиться, что она поднялась и проработала 5 секунд.

   Если не поднялась, установщик возвращает прошлую версию и запоминает номер сборки. Автообновление его пропускает, а кнопкой можно попробовать ещё раз.
6. **Переход на постоянную подпись.** Если приложение поставлено руками (скачанная ad-hoc сборка), то при первом запуске оно копирует себя, подписывает копию локальным ключом и ставит её через тот же установщик. Делается это один раз на номер сборки, поэтому зациклиться не может.

Всё пишется в `~/Library/Logs/ActivityTracker/update.log`.

## Батарея и состояние Mac

`SystemSampler` раз в минуту в фоновой очереди собирает данные в `SystemStore` (тот же файл SQLite, отдельное соединение):

| Что | Откуда |
|---|---|
| Заряд, от сети или от батареи, заряжается ли, мощность (В × А), температура, циклы, здоровье | I/O Registry → `AppleSmartBattery` (`CurrentCapacity/MaxCapacity`, `Voltage`, `InstantAmperage` как знаковое число, `Temperature` в сотых °C, `CycleCount`, `AppleRawMaxCapacity / DesignCapacity`) |
| Нагрузка процессора | `host_statistics(HOST_CPU_LOAD_INFO)`: разница тиков между замерами |
| Память | `host_statistics64(HOST_VM_INFO64)`: память приложений + неперемещаемая + сжатая (как в Мониторе системы) |
| Подкачка | `sysctl vm.swapusage` |
| Диск | `URLResourceValues.volumeAvailableCapacityForImportantUsage` |
| Тепловое состояние | `ProcessInfo.thermalState` |
| Энергия и CPU по приложениям | `proc_pid_rusage(RUSAGE_INFO_V4)`: `ri_billed_energy` (нДж) и время CPU каждого своего процесса; разница с прошлым замером, помощники приписываются приложению по пути `.app/` |

Таблицы: `system_samples` (одна строка в минуту), `app_energy` (энергия по приложениям за минуту, с отметкой «от батареи»), `charge_events` (моменты подключения и отключения зарядки).

`SystemStore.report` считает за период:
- уровень заряда и нагрузку для графиков: поминутно за день, по часам до недели, по дням дальше;
- число зарядок;
- время от батареи;
- расход в %/ч: разницы соседних минут только когда Mac от батареи, разрывы сна пропускаются, через оконные функции SQLite `LAG`;
- среднюю мощность и прогноз «полного заряда хватит на…»;
- время на 100% от сети;
- пики CPU, памяти и подкачки;
- время перегрева;
- энергию по приложениям.

## Рекомендации

`Recommendations.make` — чистая функция без сети и без ИИ. Она сравнивает «сегодня» с обычным днём (`ActivityStore.baseline`: среднее за активные дни из последних 14, без сегодняшнего). Правила:
- сайт или приложение сильно больше обычного;
- много развлечений, а истории ещё нет;
- 90 минут без перерыва (перерыв — от 5 пустых минут в минутной сетке);
- ночью за компьютером;
- очень длинный день;
- кода больше обычного (похвала);
- развлечений больше, чем кода;
- по батарее и системе: износ ниже 80%, одно приложение съело 30% и больше энергии от батареи, расход от 20%/ч, долго на 100% от сети, перегрев, мало места на диске, большая подкачка.

Советы считаются только для «сегодня», вместе с отчётом. «Обычный день» кэшируется на сутки.

## Язык

`L.tr("по-русски", "in English")`: обе строки рядом в коде, без файлов локализации. `L.current` выставляется из настройки «Как в системе / Русский / English». При смене языка корни интерфейса перестраиваются (`.id(settings.language)`), а отчёты пересчитываются, потому что тексты советов собираются в фоне. Единицы времени («5ч 12м» / «5h 12m»), байты и даты тоже следуют языку.

## Удаление данных

`ActivityStore.erase`: сайт, приложение, «всё после момента» (последние 15 мин, час, сегодня) или вся история. `PRAGMA secure_delete=ON` затирает освобождённые страницы, `wal_checkpoint(TRUNCATE)` убирает копии из WAL. Открытое событие сбрасывается. После удаления все открытые отчёты получают уведомление и перестраиваются.

## Приватные окна

Приватные окна не записываются совсем. Признаки проверяются в каждом тике:
1. AppleScript браузера: Chromium `mode of front window` = `"incognito"`, Arc `incognito of front window`.
2. Firefox: «Private Browsing / Приватный просмотр» в заголовке окна.
3. `PrivateWindowDetector`: значок «Incognito / Инкогнито / InPrivate / Private…» на панели окна. Каждое окно осматривается в фоне один раз, без содержимого страницы (`AXWebArea`) и вкладок (`AXTabGroup`). Пока окно не проверено, его тик пропускается.

У Safari публичного признака нет. Подстраховка — удаление сайта целиком из списка.

## Режимы командной строки

| Команда | Что делает |
|---|---|
| `ActivityTracker --probe` | печатает, что видят сборщики, и проверяет базу |
| `ActivityTracker --update-from-zip <zip>` | ставит сборку из zip так же, как это делает автообновление (для CI и отладки) |
| `ActivityTracker --install-update <путь>` | режим установщика (запускается сам, руками не нужен) |
| `ActivityTracker --background` | запуск без окна (после обновления) |
